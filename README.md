# 雨水调蓄池推演 Web 应用

基于 **Python + FastAPI + SciPy + 原生 JavaScript** 的雨水调蓄池（调蓄塘）连续时间
水力推演工具。后端用 SciPy 的 `solve_ivp`（DOP853）做**事件驱动**的连续时间积分，
前端用原生 JavaScript + Canvas 绘制曲线，无需任何前端构建工具；通过
**Docker Compose 一键启动**。

---

## 1. 一键启动（Docker Compose）

```bash
docker compose up --build
```

启动后在浏览器打开：

- **应用页面（水位 / 溢流结果入口）**：<http://localhost:8000/>
- 健康检查：<http://localhost:8000/api/health>
- OpenAPI 文档：<http://localhost:8000/docs>

后台运行 / 停止：

```bash
docker compose up --build -d   # 后台启动
docker compose down            # 停止并移除容器
```

> 端口在 `docker-compose.yml` 中映射为宿主机 `8000`，如被占用可把
> `"8000:8000"` 左侧改成其它端口（例如 `"18000:8000"`）。

### 不用 Docker 的本地运行方式

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
# 然后访问 http://localhost:8000/
```

## 2. 页面上如何查看水位、溢流等结果

1. 打开 <http://localhost:8000/>，页面已预填一个**三池成环 + 一根排外泵 +
   分段入流**的示例（点击“恢复示例数据”可随时还原）。
2. 填写/调整：
   - **时段**：起点、终点、输出采样点数；
   - **调蓄池**：池底高程、截面积、容量、初始水量，以及该池若干
     **分段恒定入流**（起、止时刻与非负恒定流量，可多段、未覆盖时段按 0 计）；
   - **重力管道**：起点池、终点池、管系数（单向，允许连成环）；
   - **排外泵**：所属池、额定流量、启泵水深、停泵水深、初始开关状态。
3. 点击 **“开始推演”**，结果区展示：
   - **顶部收支卡片**：初存、入流、末存、泵排、溢流、收支残差
     （`初存 + 入流 = 末存 + 泵排 + 溢流`，闭合显示 ✔）；
   - **水位过程曲线**（可切换 **水深 / 水头(水位高程) / 存水量**），鼠标悬停
     可读出各池在该时刻的数值；
   - **累计过水量曲线**（可切换 **重力管道 / 排外泵 / 溢流**），可查看每根管道
     的累计过水量、各泵累计排量、各池累计溢流随时间的变化；
   - **泵切换时刻表**：每一次开泵 ▲ / 停泵 ▼ 及其精确时刻、所属池；
   - **水量汇总表**：各管累计过水量、各泵累计排量、各池累计溢流 / 入流 / 末存。

> **溢流结果**既可在顶部“溢流”卡片看到总量，也可在“累计过水量”图切换到
> **溢流** 页签查看各池溢流的时间过程，水量汇总表中也按池列出。

输入非法（如非有限数值、非正面积/容量/管系数/泵流量、初始水量越界、
停位不低于启位、泵初态与水位阈值不符等）时，结果区**不会保留任何旧结果**，
页面顶部给出中文拒绝原因，接口返回 HTTP 422。

## 3. 计算模型

### 3.1 状态与水头

对每个池 *i*，记存水量为 *Vᵢ*：

```
水深  d_i = V_i / A_i
水头  H_i = z_i + V_i / A_i            （z_i 为池底高程）
```

### 3.2 重力管道（单向，可成环）

管道 *k* 自上游池 *u* 到下游池 *d*，请求流量按正水头差的平方根计算，
**负水头差按 0 计（绝不出现反向流）**：

```
q_k = c_k · sqrt( max(H_u − H_d, 0) )
```

管道仅在池间输水，不直接排到系统外；成环管网通过 Gauss–Seidel 固定点迭代
求解各管的实际流量。

### 3.3 排外泵（滞回开关）

泵以恒定额定流量把所属池的水**排出系统外**，按水位滞回切换：

- 水深**升至启泵水深** `depth_on` 时开启；
- 水深**降至停泵水深** `depth_off` 时关闭（要求 `depth_off < depth_on`）；
- 两阈值之间维持原状态（滞回），避免临界抖动。

### 3.4 连续时间事件推演与边界处理

把系统写成连续时间 ODE，由 SciPy `solve_ivp`（DOP853，高精度）积分，并把
下列情况作为**事件**联合处理：外部入流的分段断点、泵的开/停切换、
池的触空与触满边界。

**分段连续解的保留与采样**：推演以入流断点、泵切换、空/满事件为界逐段
连续积分；每个积分段内方程的“工况”恒定（入流恒定、泵开关固定、空/满
钉住集合固定），并保留该段 DOP853 的连续解（dense output）。输出时把
**均匀采样网格与各泵切换时刻**分别归入其所属积分段，直接取该段的连续解
求值——因此即便两池全程不触空满、中间也没有任何断点（仅靠正水头差经
管道输水），中点水位、管道累计过水量、泵排与溢流也都落在真实连续曲线上，
而**不是**在段端点间做直线插值。当采样点恰与入流断点或泵切换时刻重合时，
沿用同一刻“先更新入流与泵、再结算边界”之后的结果（即下一段的起点状态）。

**同一时刻的结算次序**固定为：

1. **先更新入流与泵状态**（入流断点右连续取新值；按当前水位做泵滞回切换）；
2. **再结算边界流量**：
   - **空池限流**：池存水量为 0 且自产水量（外部入流 + 上游各管来水）
     不足以满足全部出流请求时，其各出水管**按请求量等比例缩减**，
     保证池不被“抽干成负水量”，也不出现反向流；
   - **满池溢流**：池存水量达到容量后，泵仍可继续外排，净余水量
     （净流入扣除出流与泵排后）**计作溢流**，池水位维持在满位；
   - 全程保证 `0 ≤ V_i ≤ 容量`。

### 3.5 水量收支

系统内部管道只在池间转移水量，系统的对外水量只有“外部入流、泵排、溢流”，
因此每个工况都校验闭合关系：

```
初始存水量 + 外部入流总量 = 末存水量 + 泵排总量 + 溢流总量
```

页面与接口结果中的 `balance.residual` 即等号两侧之差（闭合时约为 0）。

## 4. HTTP 接口

`POST /api/simulate`，请求体为 JSON，字段与页面输入一致：

```json
{
  "t_start": 0,
  "t_end": 12,
  "n_points": 400,
  "tanks": [
    {"id": "A", "bottom": 10, "area": 20, "capacity": 100, "initial_volume": 0}
  ],
  "pipes": [
    {"id": "P1", "upstream": "A", "downstream": "B", "coeff": 3.0}
  ],
  "pumps": [
    {"id": "PU1", "tank": "C", "flow": 14,
     "depth_on": 3.0, "depth_off": 1.0, "initial_on": false}
  ],
  "inflows": [
    {"tank": "A", "t_start": 0, "t_end": 4, "rate": 45}
  ]
}
```

返回（节选）：

```json
{
  "times": [0.0, "..."],
  "tanks":  [{"id": "A", "depth": ["..."], "head": ["..."], "volume": ["..."],
              "inflow_total": 0.0, "overflow_total": 0.0,
              "overflow_series": ["..."]}],
  "pipes":  [{"id": "P1", "upstream": "A", "downstream": "B", "coeff": 3.0,
              "total": 0.0, "cumulative": ["..."]}],
  "pumps":  [{"id": "PU1", "tank": "C", "flow": 14,
              "depth_on": 3.0, "depth_off": 1.0,
              "total": 0.0, "cumulative": ["..."]}],
  "switches": [{"pump": "PU1", "tank": "C", "time": 6.667, "on": true}],
  "balance": {"initial": 55.0, "inflow": 320.0, "final": 203.67,
              "pumped": 65.08, "overflow": 106.25, "residual": 0.0}
}
```

命令行示例：

```bash
curl -s -X POST http://localhost:8000/api/simulate \
  -H 'Content-Type: application/json' \
  -d @example.json
```

### 输入校验（任一不满足即拒绝，返回 422，且不保留结果）

- 所有数值必须为**有限数值**（拒绝 `NaN` / `Infinity` / 非数字）；
- 截面积、容量、管系数、泵额定流量必须**严格为正**；
- 初始水量必须满足 `0 ≤ 初始水量 ≤ 容量`；
- 入流各段流量必须 **≥ 0**，同池入流段不得重叠（端点相接允许）；
- 泵必须满足 `停泵水深 < 启泵水深`；
- 泵初始开关状态必须与初始水位阈值相符（低于停位不得为开，
  达到启位不得为停；两阈值之间的滞回区可自选初态）；
- 管道 / 泵 / 入流引用的池必须存在，池 id 不得重复。
